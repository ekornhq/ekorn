# ekorn token 纪律

四条硬规则，按这个来：

1. **改文件后紧接着要跑命令 → 用 `edit_then_run` / `write_then_run`，不要改完再单独跑 shell。**
   编译、跑测试、语法检查、重启服务、`git add` —— 只要下一步动作是可预测的，就用 `then_run`
   带上，一次调用完成。这能省掉中间那次模型往返。改动失败命令不会执行；命令失败改动会保留。

2. **看到 `[ekorn-pack]` 摘要，不要重跑原命令。** 全量输出已归档在 `path:` 那行。
   用 `obs_recall`（或 `ekorn recall <id> --grep/--lines/--offset`）精确取回你要的那几行。
   重跑一遍原命令 = 白花一次执行 + 又一次大输出。

3. **定位代码先 grep，不要整份读大文件。** 大文件整份读进上下文后，
   **之后每一次请求都要重放它一遍**。先 `grep -n` 拿到行号，再用 `sed -n 'A,Bp'` 取那一段。
   同一个文件不要反复整读。

4. **命令写短。** 每次请求重放的上下文里，相当一部分是 shell 命令文本本身。
   长路径 `cd` 一次，之后用相对路径；不加 `echo "=== 标题 ==="` 之类装饰行；
   要反复用的多行脚本写成文件再按名调用，别每次整段内联。

另外：**几千行的日志/trace/大文件**，如果只有几行影响决策，交给子代理在它自己的上下文里读，
只把逐字可核验的引用带回来。看到「压缩顾问」提示时按它的判断走；在计划边界主动压，比被动压丢得少。
